# Codex-X-Pro 本地网关页面 UI 调整实施文档

## 1. 文档目的

本文用于指导 Codex-X-Pro 本地网关相关页面的 UI 重组和样式统一。

本次调整只涉及：

- 侧栏导航顺序；
- 本地网关、实时请求观测、用户脚本处理器三个页面的拆分；
- 页面标题、布局、间距、字体、按钮、状态标签、输入控件和弹窗样式统一；
- 页面之间共享已有的网关运行时状态和刷新机制。

本次调整不得涉及：

- 网关后端协议、控制接口和错误码；
- 网关启动、停止、恢复、看门狗和端口行为；
- Provider、指令提示词和 Canonical State；
- 观测数据采集、SSE 推送、脱敏、保留上限和 Tokens 统计；
- 用户脚本协议、测试、启用、停用、优先级和执行链；
- 任何已有功能的删除、替换、弱化或新增。

目标是让三个页面在视觉上属于同一套 Codex-X-Pro 工具界面，同时让用户能够分别进入网关控制、请求观测和脚本管理页面。

## 3. 目标导航结构

### 3.1 侧栏顺序

侧栏使用现有扁平导航，不新增折叠菜单，不新增二级路由系统。

目标顺序如下：

```text
概览
供应商
会话管理
技能和 MCP
指令提示词
TOML
本地网关
实时请求观测
```

其中：

- “本地网关”必须位于“设置”上方；
- “实时请求观测”紧跟在“本地网关”下方；
- “用户脚本处理器”紧跟在“实时请求观测”下方；
- 三个页面应保持连续排列，便于用户理解它们属于同一组网关工具；
- 不重复显示旧的“网关”入口；
- 不在“设置”页面内部再增加网关入口。

页面标识：`gateway`

本页只保留当前本地网关控制页面的内容：

- 页面标题“本地网关”；
- 网关运行状态；
- 监听端口输入；
- 上游地址输入；
- 启动网关；
- 停止网关；
- 刷新网关状态；
- 网关守护状态；
- 看门狗实际运行状态；
- 登录自启动状态；
- 网关改动重启 Codex 提示；
- 外部网关未接管提示；
- 网关未运行或降级时的状态提示；
- 网关错误和错误原因展示；
- 当前运行时提交状态的展示。

本页不得继续放置：

- 实时请求观测表格；
- 观测启动、暂停、清除、筛选、排序和保留上限控件；
- 用户脚本列表；
- 脚本测试、测试详情、协议说明、启用、停用和优先级控件。

本页保留现有网关启动、停止、刷新、端口校验和状态判断行为。拆分后不得因为观测页或脚本页未打开而改变网关状态。

- 当前保留数；
- 保留上限；
- 淘汰数量；
- 丢弃数量；
- 请求观测列表；
- 空列表和未进入网关模式提示；
- 错误行浅红色状态；
- 请求详情弹窗；
- 探针选择；
- `raw-text` 视图；

本页不得拥有或复制：

- 上游地址编辑；

## 7. 状态和数据流约束

### 7.1 共享状态来源

三页必须使用同一套运行时状态来源：

```text
get_gateway_process_state({ listenPort })
start_gateway({ input: { listenHost, listenPort, upstream, configDir } })
stop_gateway()
gateway_request({ input: { listenPort, method, path, body } })
localStorage["codexx.gateway.port"]
codexx-gateway-state-changed
codexx-gateway-port-changed
```

不得出现以下情况：

- 每个页面各自保存一个互不一致的网关端口；
- 一个页面认为网关已运行，另一个页面认为网关未运行；
- 页面切换后重新启动网关；
- 页面切换后清空观测数据；
- 页面切换后重复执行脚本测试；
- 通过前端乐观状态宣称网关、观测或脚本已经生效。

### 7.2 页面挂载策略

可以采用以下任一方式：

1. 三个页面按需挂载，并在页面进入时读取当前网关状态；
2. 三个页面在首次访问后缓存已读取的视图状态，离开页面时停止仅属于该页面的订阅。

无论采用哪种方式：

- 网关进程状态轮询必须由共享层或当前页面安全维护；
- 观测 SSE 只在实时请求观测页面需要时建立；
- 离开观测页必须关闭 EventSource 和重试定时器；
- 离开脚本页不应清除网关中的脚本测试结果；
- 页面重新进入时必须从后端重新读取真实状态。

### 7.3 状态禁用规则

沿用当前 `gatewayState.ts` 的语义：

- `stopped`：网关未运行；
- `managed`：由 Codex-X-Pro 接管的网关正在运行；
- `external`：存在运行中的外部网关，但 Codex-X-Pro 未接管。

实时请求观测页：

- 只有 `managed` 状态允许观测运行时控制；
- `stopped` 和 `external` 状态显示不可用提示；
- 不得对外部网关执行停止、观测控制或脚本链控制。

用户脚本处理器页：

- 保留脚本查看、刷新和协议测试的现有可用性；
- 真实脚本链的启用/禁用状态必须继续由后端状态和现有禁用条件决定；
- 不得因页面拆分而把直连模式测试变成真实请求处理。

## 8. 统一 UI 规范

### 8.0 强制统一原则

本节为强制性实施要求，不是视觉建议。

三个网关页面必须与项目现有页面使用同一套 UI 规范，优先复用已经存在的组件、CSS 类、设计变量和交互状态。实现时必须先检查以下已有资源：

- `apps/desktop/src/components/ui/Button.tsx`
- `apps/desktop/src/components/ui/IconButton.tsx`
- `apps/desktop/src/components/ui/StatusBadge.tsx`
- `apps/desktop/src/components/ui/ModalShell.tsx`
- `apps/desktop/src/styles/ui-primitives.css`
- `apps/desktop/src/styles/utility-pages.css`
- Provider、会话、Skills/MCP 和提示词页面中已经存在的通用控件样式。

必须遵守以下规则：

- 能复用已有组件时，必须复用已有组件；
- 能复用已有 CSS 类或设计变量时，必须复用已有 CSS 类或设计变量；
- 网关页面不得为已有按钮、图标按钮、状态标签、弹窗、输入框、选择器和字段标签重新定义一套同类样式；
- 网关页面的自定义 CSS 只能描述网关特有的布局、表格列、观测行、脚本卡片内容和页面专属状态，不得复制基础控件的视觉定义；
- 不得通过更高优先级选择器覆盖共享组件，使网关页面出现不同的字号、字体、按钮高度、圆角、边框、颜色或交互状态；
- 不得为了“页面看起来独立”而保留旧的网关专用按钮、弹窗、输入框或状态标签样式；
- 如果现有共享组件无法满足需求，应先扩展共享组件或共享样式，再由三个网关页面共同使用，不得只在单个网关页面内新增同类自定义实现；
- 页面特有布局样式与基础组件样式必须分离，不能在同一个选择器中同时复制布局和控件视觉规则；
- 完成后必须删除已被共享组件替代的网关页冗余 CSS，并检查没有遗留无效类名。

最终效果要求：用户在本地网关、实时请求观测、用户脚本处理器、Provider、提示词、会话和 Skills/MCP 页面之间切换时，按钮、字段、状态标签、弹窗、正文和辅助文字应保持同一套视觉语言。允许页面因内容不同而使用不同布局，但不允许因为页面不同而使用不同的基础控件样式。

### 8.1 页面外框

三个页面统一使用与其他工具页面一致的页面外框：

```text
section.cx-utility.cx-page
```

不得另行创建只服务于网关页面的基础页面外框。若需要调整页面内距、滚动或布局，必须复用或扩展共享页面类，并确保其他页面不会出现不一致的基础排版规则。

统一要求：

- 页面最大宽度和左右内边距与 `UtilityPages`、Provider、Skills/MCP 页面保持一致；
- 页面标题使用统一的 `PageHeader` 视觉层级；
- 页面描述使用统一的正文颜色、字号和行高；
- 页面区块之间使用统一间距；
- 页面背景、面板、分隔线、标题、辅助文字和控件颜色使用现有设计变量；
- 不使用新的大圆角、渐变背景或装饰性浮层；
- 卡片圆角不超过现有设计系统要求；
- 保持浅色和深色主题下的对比度。

### 8.2 按钮

当前网关页已有 `ui-button` 类名，但按钮仍在页面中直接书写，且部分图标按钮、保存按钮和关闭按钮使用独立样式。这些重复实现必须清理。

统一改造要求：

- 所有文本按钮必须使用 `Button` 组件；
- 所有纯图标按钮必须使用 `IconButton`；
- 删除网关页面中可由共享组件替代的原生按钮及其 CSS；
- 启动、停止、刷新、暂停、清除、测试、重试、详情、启用、禁用、恢复默认、运行测试等按钮统一使用 `Button`；
- 关闭弹窗、保存保留上限等纯图标动作统一使用 `IconButton`；
- 统一使用 `primary`、`secondary`、`danger`、`ghost` 变体；
- 统一使用 `sm`、`md`、`lg` 尺寸，不在页面 CSS 中重新定义相同按钮高度和字号；
- 所有图标继续使用 `lucide-react`；
- 按钮的 disabled、focus、hover、active 状态使用共享 UI 原语行为；
- 保留当前动作语义：启动/启用可使用 `primary`，停止/禁用可使用 `danger`，查询/刷新/详情可使用 `secondary`；
- 网关页面不得继续保留 `.cx-gateway-limit button`、`.cx-gateway-modal-head button` 或其他同类自定义按钮视觉规则。

不得用 CSS 覆盖把不同页面的 `Button` 或 `IconButton` 重新做成不同高度、不同字体、不同圆角、不同边框或不同 hover/focus 行为。

### 8.3 状态标签

脚本状态和网关状态必须使用 `StatusBadge` 或项目已有的等价共享状态标签，且必须按以下统一 tone 映射：

| 当前状态 | 统一 tone |
| --- | --- |
| 未启动、未测试、不可用 | `neutral` |
| 启动中、测试中、外部状态 | `warning` 或 `info` |
| 已运行、测试通过、已启用 | `success` |
| 测试失败、执行失败、降级 | `danger` |
| 当前模式或已提交版本 | `accent` |

脚本状态文字仍可保留当前中英文案。统一的是视觉组件、尺寸、间距和状态色，不改变状态值。不得为脚本状态单独保留 `.cx-gateway-script-status` 的完整视觉实现；页面只能保留状态映射或必要的布局类。

### 8.4 输入、选择器和标签

端口、上游地址、保留上限、优先级、筛选和详情视图选择器统一使用同一套控件尺寸：

- 统一最小高度；
- 统一边框颜色；
- 统一背景色；
- 统一字体；
- 统一 focus ring；
- 统一 disabled 表现；
- 统一 label 字号和 label 与控件之间的间距。

网关页输入规则必须收敛到共享类或现有共享组件，例如：

```text
ui-field
ui-field__label
ui-field__control
ui-select
```

如果项目当前已有可用字段类，必须直接复用；如果确实缺少能力，只能在共享 UI 层补充一次，然后由其他页面和三个网关页面共同复用。不得在三个网关页面分别复制输入样式，也不得在单个网关页面内为相同控件创建多个版本。

### 8.5 字体

页面正文统一继承应用字体：

```css
Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif
```

仅以下内容允许使用等宽字体：

- raw-text；
- JSON；
- 协议说明；
- 详情正文；
- 路径、ID、端口或需要明确等宽对齐的技术字段。

等宽内容统一使用：

```css
ui-monospace, SFMono-Regular, Consolas, monospace
```

不得继续在同一页面中混用多种不必要的字体族、字号和行高。页面标题、区块标题、正文、辅助说明、表格和状态文字必须与其他页面保持同级字号。网关页面 CSS 不得通过局部选择器把同级文本设置成另一套字号或字体。

### 8.6 弹窗

观测详情、脚本测试和协议说明必须迁移到 `ModalShell` 或基于它的共享弹窗结构：

- 统一遮罩；
- 统一标题栏；
- 统一关闭按钮；
- 统一内容滚动；
- 统一 footer 按钮布局；
- 统一键盘 Escape 行为；
- 统一移动窗口尺寸；
- 保留当前各弹窗的内容、测试输入和详情视图。

弹窗内的 raw-text、JSON 和错误详情继续使用等宽字体，但弹窗标题、说明和按钮必须使用普通页面字体。不得继续保留 `.cx-gateway-modal`、`.cx-gateway-modal-head button` 等与 `ui-modal`、`ui-icon-button` 重复的基础弹窗样式。

## 9. CSS 重组方案

### 9.1 样式分层

建议按以下层次整理：

```text
ui-primitives.css
  按钮、图标按钮、状态标签、弹窗、基础控件

utility-pages.css
  页面标题、页面外框、通用面板、通用字段布局

gateway-page.css
  本地网关页面的网关状态和启动控制布局

gateway-observe-page.css
  观测工具栏、表格、排序表头、错误行和详情内容

gateway-scripts-page.css
  脚本卡片、脚本状态、优先级控件和测试区域

dark-theme.css
  三个页面的深色主题变量和必要覆盖
```

### 9.2 旧样式清理

以下当前网关页中的重复样式必须删除或重构为共享样式，不能在拆分后原样保留：

- `.cx-gateway-script-actions button` 等按钮重复定义；
- `.cx-gateway-limit button` 的独立保存按钮样式；
- `.cx-gateway-modal-head button` 的独立关闭按钮样式；
- 页面内重复设置的按钮字号、最小高度和边框；
- 与 `.ui-button`、`.ui-icon-button`、`.ui-modal` 重复的弹窗和控件样式；
- 与通用页面标题、面板和字体规则重复的样式。
- `.cx-gateway-script-status` 和 `.cx-gateway-script-enabled` 中可由 `StatusBadge` 替代的状态标签视觉规则；
- 网关页面中重复设置的输入框、选择器、label 字号、focus ring、disabled 状态和圆角；
- 仅为了覆盖共享组件而添加的页面级高优先级选择器；
- 已经不再被 JSX 使用的旧网关类名和对应媒体查询。

删除重复 CSS 前必须确认对应元素已经替换为共享组件，不能只删除样式而留下无样式原生控件。清理完成后必须搜索网关页面 JSX 和 CSS，确认没有无效类名、重复按钮实现或未使用的网关专用基础样式。

### 9.3 深色主题

深色主题必须覆盖三个页面的：

- 页面背景；
- 面板背景；
- 边框；
- 标题和正文；
- 辅助文字；
- 输入和选择器；
- 表格表头和悬停状态；
- 错误行；
- warning 提示；
- 状态标签；
- raw-text/JSON 内容区；
- 弹窗遮罩和弹窗主体。

不得仅通过降低整个页面 opacity 来表达未运行状态，否则会导致按钮文字和错误提示对比度不足。未运行状态应使用明确的状态区域和控件禁用状态表达。

## 10. 页面标题和文案

三个页面均需支持中英文。

建议文案：

| 页面 | 中文标题 | 英文标题 | 中文说明 |
| --- | --- | --- | --- |
| 本地网关 | 本地网关 | Local gateway | 控制本机转发和网关运行状态。 |
| 实时请求观测 | 实时请求观测 | Live request observation | 查看网关运行期间的受限请求观测记录。 |


直连模式下使用醒目的 warning 样式；网关运行且脚本链可用时显示实际后端状态，不得根据按钮颜色提前宣称“已生效”。

## 11. 实施步骤

### 第一阶段：导航和页面壳

1. 在 `AppShell.tsx` 增加两个页面标识和导航项。

### 第二阶段：拆分现有 JSX 和状态

6. 保持现有 localStorage key、事件名称和状态类型不变。

### 第三阶段：统一 UI 原语

1. 将网关页面原生文本按钮替换为 `Button`。

### 第四阶段：样式和主题校准

1. 重组网关相关 CSS 文件。
