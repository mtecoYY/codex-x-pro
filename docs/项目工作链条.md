## raw-text 用户脚本协议

### 输入格式

每次真实请求启动一个脚本进程。网关把一份完整的请求文本按原始字节写入脚本 `stdin`，写完后关闭 `stdin`；脚本读到 EOF 即表示输入结束。

请求文本采用 Reqable 等抓包工具常见的格式：

```text
METHOD /path?query HTTP/2\r\n
header-name: header-value\r\n
content-type: application/json\r\n
content-length: <length>\r\n
\r\n
<request body bytes>
```

请求行、请求头、空行和正文的排列方式与上面的示例一致。正文可以是 JSON，也可以是任意其他字节；网关不得因为正文不是 JSON 就替换或丢弃它。`Content-Length` 表示正文实际字节数，不以字符数计算。

下面的抓包只用于说明格式，不是固定的业务请求，也不包含真实认证值或用户查询：

```text
POST /widget/telemetry HTTP/2\r\n
host: rewards.example.test\r\n
content-type: application/json\r\n
user-agent: ExampleBrowser/1.0\r\n
content-length: <length>\r\n
\r\n
{"userId":"","partnerId":"Example","events":[]}
```

### 输出格式

脚本把修改后的完整请求文本写入 `stdout`，同样使用请求行、请求头、空行和正文的 raw-text 格式；调试信息只能写入 `stderr`。一次调用只能输出一份请求文本，不能输出 JSONL、日志或额外说明。

脚本可以修改请求行、路径、查询参数、HTTP 版本、任意请求头和完整正文，包括 `model`、提示词内容及其他业务字段。网关在实际发送前可以重新计算 `Content-Length`、移除 hop-by-hop 头部并执行必要的连接层规范化；这些是传输层整理，不限制脚本修改请求内容的权限。

固定 Provider 上游仍由网关运行时配置决定。脚本可以修改 raw-text 中的 `Host` 等请求头，但不能通过请求文本改变网关实际连接的 Provider 目标；如未来需要脚本选择上游，必须另行扩展路由权限协议。

### manifest 与执行结果

使用 raw-text 的脚本 manifest 必须声明出口格式为 `raw-text`，并声明一次调用只处理一份请求：

```json
{
  "protocol_version": 1,
  "id": "my-raw-rewriter",
  "name": "My Raw Rewriter",
  "description": "Rewrite raw HTTP request text",
  "version": "1.0.0",
  "entry": {"program": "python", "args": ["main.py"]},
  "exit": {"format": "raw-text", "one_request_per_process": true},
  "directions": ["request"]
}
```

raw-text 仍保留用户脚本的串行链和失败阻断规则：上一支脚本的 `stdout` 是下一支脚本的 `stdin`，脚本链结束后的文本才允许发送到 Provider。脚本超时、退出码异常、输出无法解析为请求文本或没有输出时，当前请求立即停止，网关返回 `SCRIPT_EXECUTION_FAILED`，不得把半成品发送给上游。

为保留当前用户脚本的 `forward`、`respond`、`drop`、`error` 语义，raw-text 版本使用进程退出码作为控制通道：

```text
0       stdout 是修改后的请求 raw-text，继续 forward
10      stdout 是完整 HTTP 响应 raw-text，直接 respond 给客户端
11      丢弃请求；stderr 提供可展示的原因
其他非零  执行失败；stderr 提供错误详情，等价于 error
```

`stdout` 只能包含协议文本，日志只能写入 `stderr`。响应 raw-text 使用状态行、响应头、空行和响应正文的格式；`drop` 不要求 stdout 输出正文。控制信息不能通过把日志混入请求正文来表达。

## 探针与详情页面

探针只负责保存某个阶段的请求或响应快照，不限制快照的展示格式。所有探针（包括全局入口探针、提示词注入探针、全局出口探针和响应探针）使用同一个详情查看器，用户可以在详情页直接切换：

1. `raw-text`：显示该探针捕获的完整 HTTP 文本；请求探针显示请求文本，响应探针显示响应文本。
2. `request body JSON`：仅当快照包含可解析的请求正文时显示格式化 JSON。
3. `response body JSON`：仅当快照包含可解析的响应正文时显示格式化 JSON。

详情视图不根据探针名称硬编码。提示词注入探针同样必须能够切换到 `raw-text` 和请求体 JSON；响应体 JSON 在该探针没有响应正文时显示为不可用，而不是伪造内容。正文超过保留上限时，界面必须同时显示 `OBSERVE_DETAIL_TRUNCATED`、已保留字节数和原始字节数。

观测记录仍需按统一规则脱敏认证信息、Cookie、Token 和其他敏感字段。raw-text 视图也必须脱敏；“raw”表示格式和字段布局，不表示绕过观测脱敏。

## tool-call ID 修复用户脚本

 tool-call ID 修复不再作为 Codex-X-Pro 项目控制层内置的后置处理，而是一个普通的用户脚本，遵循用户脚本目录、manifest、测试、启用、优先级、超时和失败阻断规则。它的功能必须与当前个人网关的修复行为一致：

```text
custom_tool_call: fc_xxx -> ctc_xxx
tool_search_call: 保持原值
function_call 的 fc_xxx 不修改
历史错误消息中的文本不修改
```

该脚本是当前用户的个人自定义脚本，只保存在本机用户脚本目录，不随项目发布，不加入 Git 提交，也不能作为其他用户安装后的必备文件。网关仓库中不得再保留一份会自动执行的同名内置修复路径；是否启用、优先级和脚本版本均以本机用户脚本配置为准。
